# Home screen widget

A calendar whose whole thesis is "most days are empty" wants to tell you your
next Red Letter day without being opened. That is what these are for.

## Status: written, not wired in

**These sources are not part of the build.** `npx expo prebuild` does not
touch them, and the app builds and runs on both platforms without them.

They are separate on purpose. Adding an iOS widget extension means generating a
second Xcode target, and a config plugin that gets that wrong breaks
`expo prebuild` for the whole project. Rather than risk the working app on code
that cannot be compiled or run in the environment it was written in, the widget
is checked in as complete, reviewable sources with the integration steps below.

**Neither file has been compiled.** Budget time for the usual first-build
friction — signing, target membership, Glance dependency versions.

Everything they display is already tested: `buildWidgetSnapshot` in
`src/features/widgetSnapshot.ts` computes the wording and the date arithmetic,
and `__tests__/widgetSnapshot.test.ts` covers it. The widgets only render.

## What is still missing

One native module that writes the snapshot out of JavaScript. It needs three
small pieces:

1. **iOS** — write the JSON string to `UserDefaults(suiteName:)` for the App
   Group, then call `WidgetCenter.shared.reloadAllTimelines()`.
2. **Android** — write the same string to `SharedPreferences` named
   `redletter.widget`, then broadcast an app widget update.
3. **JS** — call it whenever the data changes, from `ReminderSync.tsx`, which
   already has the debounced hook for exactly this.

Write it as a local Expo module (`npx create-expo-module --local`). The payload
is `serialiseWidgetSnapshot(buildWidgetSnapshot(data, todayKey()))`.

## The snapshot

```json
{
  "version": 1,
  "hasNext": true,
  "title": "Anniversary",
  "distance": "In 3 weeks",
  "longDate": "Saturday, 14 March",
  "date": "2026-03-14",
  "count": 1,
  "builtFor": "2026-02-21"
}
```

**Only the next day is ever written.** Not the rest of the calendar — see the
note on `widgetSnapshot.ts` for why this is deliberately the smallest thing
that answers the question.

### Security note

Widget extensions run in a separate process that cannot reach the app's
Keychain key, so anything a widget displays has to live outside the encrypted
store. This one line does; the rest of the calendar never leaves the encrypted
file.

That line is plaintext in a shared container, so **writing it should be
opt-in** — add a Settings switch and write nothing until it is on. The title is
in any case about to be shown on a home screen where anyone holding the phone
can read it, so the snapshot adds only the exposure the user asked for. That
reasoning stops holding if the payload ever grows, so keep it to one day.

The shared container is also excluded from Android backup by
`plugins/withRedLetterSecurity.js`, which excludes `domain="root"`.

## iOS integration

1. In Xcode, **File → New → Target → Widget Extension**, named
   `RedLetterWidget`. Uncheck "Include Live Activity" and "Include
   Configuration App Intent".
2. Replace the generated Swift with `ios/RedLetterWidget.swift`.
3. **Signing & Capabilities → + App Group** on *both* the app target and the
   widget target. Use `group.com.redletter.app`, or change
   `appGroupIdentifier` in the Swift file to match what you use.
4. Because `ios/` is generated by prebuild and gitignored, do this through a
   config plugin before shipping, or the target is lost on the next
   `expo prebuild --clean`. [`@bacons/apple-targets`](https://github.com/EvanBacon/expo-apple-targets)
   is the usual way; it was deliberately not added here so the build has no
   unverified dependency on it.

## Android integration

1. Copy `android/RedLetterWidget.kt` to
   `android/app/src/main/java/com/redletter/app/widget/`.
2. Add Glance to `android/app/build.gradle`:
   ```gradle
   implementation "androidx.glance:glance-appwidget:1.1.1"
   ```
3. Register the receiver in `AndroidManifest.xml`:
   ```xml
   <receiver android:name=".widget.RedLetterWidgetReceiver"
             android:exported="false">
       <intent-filter>
           <action android:name="android.appwidget.action.APPWIDGET_UPDATE" />
       </intent-filter>
       <meta-data android:name="android.appwidget.provider"
                  android:resource="@xml/red_letter_widget_info" />
   </receiver>
   ```
4. Add `res/xml/red_letter_widget_info.xml` with your preferred sizing.
5. As with iOS, `android/` is generated, so move steps 1–4 into
   `plugins/withRedLetterSecurity.js` (or a sibling plugin) before shipping.

## Design

Both widgets follow the app: paper, ink, and red used for exactly one thing —
how far away the next marked day is. No progress rings, no counts of what you
have done, no streak. The empty state says "The year is open," because in this
product an empty calendar is the goal and not a prompt to fill it in.
